# Codex run history

Use the transcript lookup in [Codex tool mapping](codex-tools.md#tool-actions). Before opening history, identify the canonical working directory and its Git worktrees (use `git worktree list --porcelain` for a Git project). For an eval, record each candidate's Codex thread ID from the dispatch result and the directory assigned for its work. Find the transcript by that exact thread ID. A spawned agent can inherit the parent session's launch directory in `session_meta.cwd` even when it works elsewhere. Check that its commands and artifacts stayed within the assigned scope separately.

For pickup or history mining, match the `session_meta` record to the allowed workspace and, where known, to the exact thread ID. For eval, use the recorded thread ID and confirm any expected launch directory separately from the assigned work directory. For a thread with more than one rollout, use only the current rollout from Codex's state index. Treat missing or ambiguous history as unavailable. When resuming without a transcript, continue with the cloud-agent URL or pushed branch if one was provided. When evaluating or mining history, report the missing evidence rather than substituting a different transcript or relying on a candidate's summary.
