# Setup pstack on Devin CLI

On Devin CLI, follow this procedure instead of steps 1 through 7 of [setup-pstack](SKILL.md). Steps 8 and 9 still apply. This procedure uses the same role keys as step 6, but no Claude model defaults. Every choice comes from the user's answers or their saved sheet.

## Detect models and load choices

Run `devin models list` through `exec`. Use the complete UID column exactly as listed. Availability depends on the account and organization. Do not invent IDs or substitute Claude aliases. If the listing fails, report the failure and keep model setup incomplete.

Resolve the global configuration directory by running `printf '%s\n' "${XDG_CONFIG_HOME:-$HOME/.config}/devin"`. Read `pstack-models.md` in that directory if it exists. Treat its known role lines as current choices. Drop retired role keys. Keep valid saved UIDs unchanged. A saved value that is no longer listed needs a new user choice.

## Confirm choices

Use `ask_user_question` to ask for a default UID, a strongest UID, and the panel's list of UIDs. Show the detected IDs and the saved values. Offer `inherit-parent` as a choice, and accept saved `auto` with the same meaning. Both select `subagent_general`, which inherits the parent model. Each panel entry still creates one reviewer or candidate. Ask which individual roles need another choice, then confirm every role using the keys in step 6 of the shared skill.

Prefer distinct model families for panels. Report reduced diversity when only one family is available or the user chooses it. Do not replace a required independent reviewer with the parent.

A model's thinking level is part of its complete UID. Devin's `run_subagent` has no model or reasoning-effort parameter. Do not append or interpret `@effort` suffixes. Set `default effort: session`. A saved suffix needs a confirmed concrete UID from the current listing.

Ask whether to keep the SessionStart routing hook on. Preserve the saved choice on a re-run. With no answer, do not invent model choices or write the sheet. In a noninteractive session, report the missing choices and use `inherit-parent` only for the current task when its workflow permits that fallback.

## Write the sheet and profiles

Validate every concrete UID against the listing. Use step 6's role keys and one line per role, with the user's confirmed UID or inheritance choice. Put this header above those lines:

```markdown
# pstack model configuration

Per-role model choices for pstack on Devin CLI. Concrete UIDs select profiles generated by setup-pstack. `inherit-parent` and `auto` select `subagent_general`. Panels dispatch one child per entry. Thinking levels are part of the UID. Rerun setup-pstack to change these choices.
```

End the sheet with `default effort: session` and the confirmed `session hook: on` or `session hook: off`. Write the whole file at the resolved configuration path. Node.js is required for the bundled helper.

For each distinct concrete UID, run the helper below. Replace both placeholder paths with absolute paths. The agents directory is `agents` inside the resolved Devin configuration directory.

```shell
node /absolute/path/to/setup-pstack/scripts/devin-profile.mjs --model <confirmed-UID> --agents-dir /absolute/path/to/devin/agents
```

The command prints the exact profile name. It creates only an absent file, accepts an identical existing file without changing it, and refuses a conflicting file. On conflict, report the path and preserve it. Do not delete old profiles or modify installed plugin files.

The generated profile has the exact model UID and all normal tools. It has no nested delegation enabled. Pass the role's full semantic instructions with each task, including the appropriate workflow or agent reference, write permissions, and worktree path. The profile does not replace those instructions.

## Verify discovery and future sessions

Inspect the system context block that begins `Available subagent profiles for the run_subagent tool`. It lists the discovered profile names. Confirm every generated profile is visible before saying setup is ready for dispatch. If a profile is absent, tell the user to start a new Devin session, then verify it there. A file's existence alone does not prove discovery.

Future sessions read the sheet and resolve a saved concrete UID through the same installed helper without writing files:

```shell
node /absolute/path/to/setup-pstack/scripts/devin-profile.mjs --model <saved-UID> --name-only
```

Pass its printed name as `run_subagent.profile`. Never derive a profile name by hand, pass a UID as the profile, or put `model` on the tool call. For `inherit-parent` or `auto`, select `subagent_general` without generating a profile.

No include line is needed. The native hook reads only the exact `session hook: off` setting and points to the [Devin mapping](../poteto-mode/references/devin-tools.md). It does not inject the sheet. Skills-only installs still carry this helper and read the same sheet. They need an explicit `poteto-mode` invocation or a standing instruction in the project's `AGENTS.md` to route tasks automatically.
